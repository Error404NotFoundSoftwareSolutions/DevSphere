# Your next real contribution

You just did the full contribution cycle: read the rules, branch, fix, test, document, commit, describe, respond to a review. The only thing missing was the internet, and that part is easy.

## What you can now say honestly

- I can read an unfamiliar project and its contribution rules.
- I work on branches and write clear commit messages.
- I write a test that proves a fix.
- I write a pull request description a maintainer can act on.
- I can handle review feedback professionally.

## Your first real pull request: a checklist

1. Make a free GitHub account if you do not have one, and set up Git with your name and email.
2. Find a small project you actually use. Read its `README.md`, `CONTRIBUTING.md` and code of conduct.
3. Look at issues labelled `good first issue`, `help wanted` or `documentation`. Sites that collect them: `goodfirstissue.dev` and `firsttimersonly.com`.
4. Comment on the issue: "I would like to work on this. Is it still open?" Wait for a yes.
5. Fork, clone, branch, fix, test, commit, push.
6. Open the pull request with the same description structure you wrote here.
7. Answer the review kindly and promptly.

## Good first targets

- Documentation: typos, unclear steps, broken links, missing examples.
- Tests: a missing test for a function that already works.
- Error messages: make one clearer.
- Small bugs that are already reproduced in the issue.

Avoid: huge features, "refactor everything" ideas, projects that have been silent for years, and anything that asks you to skip the project's rules.
