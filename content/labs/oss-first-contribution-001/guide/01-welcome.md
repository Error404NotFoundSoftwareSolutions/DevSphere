# What open source is and why it matters

Almost every app you use is built on **open-source software**: code that anyone may read, use, change and share, under a licence that says how. Linux, Python, Git, VS Code, Android's core and most web frameworks are open source.

## Why contributing is worth your time

- **Proof of skill.** A merged pull request is public evidence that you can read someone else's code, change it safely and work with a team. Recruiters can open it.
- **Real code.** Tutorials are small and clean. Real projects have history, tests, rules and reviewers. You learn how software is actually made.
- **Habits employers pay for.** Branches, commits, code review, writing issues and being polite in public are daily work in every company.
- **A network.** Maintainers remember people who help.

> You do not need to be an expert. Many of the most welcome contributions are small: a typo, a clearer error message, a missing test, a wrong example in the docs.

## The words you will meet

- **Repository (repo):** the project folder plus its full history.
- **Maintainer:** a person who decides what goes into the project.
- **Issue:** a written report of a bug or a request.
- **Pull request (PR):** your proposal to add your change to the project.
- **Review:** maintainers read your change and ask for improvements.
- **Merge:** your change becomes part of the project.
- **Licence:** the rules for using the code, for example MIT.

## What you will do in this lab

You will contribute to a tiny practice project called **pyslug**. On your own computer, with real Git, you will:

1. Turn the project into a repository and make the first commit.
2. Fix a bug on its own branch and merge it.
3. Fix a documentation mistake.
4. Fix a second bug, with a test that proves the fix.
5. Write the pull request description a maintainer expects.
6. Answer a review comment with a follow-up commit.

Nothing here touches the internet, so you cannot break a real project. The habits are exactly the ones you will use on GitHub.
