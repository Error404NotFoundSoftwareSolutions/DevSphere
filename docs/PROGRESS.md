## 2026-11-11: videos play inside the app (embedded Chromium)
- First attempt, a native WebKitGTK view (webview_win_floating), broke Flutter's drawing on Linux: the whole window went black ("Could not make the context current"), under X11 and Wayland, with Impeller and Skia, with and without the snap. Flutter on Linux cannot draw without the GPU, and WPE WebKit is not packaged for Ubuntu 26.04.
- Now: `webview_cef` runs Chromium (CEF 149) off-screen and draws it into a Flutter texture, so the player is an ordinary widget inside the Watch tab (dialogs can draw over it). Checked on this machine with captured screenshots: Flutter header plus a playing YouTube video, zero GL errors; the full app starts normally. `linux/main.cc` and `windows/runner/main.cpp` start Chromium's helper processes (the plugin's required hooks); `linux/my_application.cc` forwards keyboard input.
- Watching is measured as before: the player page counts only seconds played in order and reports every 4 seconds under a random session (`POST /v1/player/sessions`, `POST /player/progress`, `GET /v1/player/sessions/{id}`); the Watch tab reads it every 3 seconds. If the embedded browser cannot start within 20 seconds (or the service is down), the tab falls back to the DevPilot player window (an app-mode browser window).
- Costs: the first build downloads CEF (about 330 MB) and the debug app bundle grows to about 1.9 GB (mostly CEF; a release build is smaller); on Linux frames are copied in software (more CPU), Windows and macOS use the GPU. CEF keeps its profile in `~/.config/cef_user_data` (the plugin's default). macOS needs the plugin's CocoaPods step (not set up yet).
- Tests: API 1 new, app 5 new (player window, embedded fallback). All app tests pass (187).
- Fix after testing: the plugin drew Chromium's hover hint (the video title) into the app's overlay and sometimes never removed it. The player page now removes the title from the YouTube frame, and the video has its own overlay, so any hint stays inside it and goes away with it. The video choice uses the app's pill tabs (the selected chip was unreadable).
- The Chromium that the plugin downloads has no H.264, so a few YouTube videos (or ads) cannot play inside the app ("FFmpegDemuxer: no supported streams"). The player page now reports playback errors to the API, and the Watch tab switches that video to the DevPilot player window (normal Chrome plays every format), with a note; it does the same when a video has not started 30 seconds after loading.

## 2026-11-12: lab generator timeout fix
