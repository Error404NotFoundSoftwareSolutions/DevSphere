# Backend API

OpenAPI is generated by the FastAPI app (`services/api`) and is the contract; the typed client in `packages/api-client` is generated from it. This page is the human summary.

Conventions: HTTPS only, JSON, URL-versioned (`/v1`). Bearer token on every protected call. State-changing calls accept `Idempotency-Key`. Errors: `{ code, message, recovery, correlation_id }`. Lists are paginated. Rate limits apply to sign-in related, tutor, submission and profile endpoints.

|---|---|---|

## Open-source contribution endpoints (proposed, ADR-023, R3)

Status: proposed, pending owner approval. Stories: US-R3-8 to US-R3-13 in `docs/backlog/oss_flow_proposals.md`. All `/v1/oss/*` calls need a bearer token. The extension uses an attempt-scoped session that works only for its own `/v1/oss/attempts/{id}/*`. A user ID, score, trust level or milestone state supplied by a client is ignored.

| Method and path | Purpose | Trust of what it records |
|---|---|---|
| `POST /v1/oss/attempts` | Create the OSS attempt (the app calls this) and return a single-use, 5-minute launch code for `vscode://` | n/a |
| `POST /v1/oss/session` | Exchange a launch code for the attempt-scoped session | n/a |
| `POST /v1/oss/link` | Start GitHub link. Returns the authorize URL (state, PKCE). Needs a recorded age-check outcome | n/a |
| `GET /v1/oss/link/callback` | GitHub redirects here (public, state checked). Stores numeric ID and login, discards the user token, redirects to the `vscode://` link-back with no secrets | High (account linked) |
| `GET /v1/oss/attempts/{id}` | Milestone list: milestone, status, source, trust (`high` or `hint`), label (`Verified` or `Practice (unverified)`), evidence time | n/a |
| `POST /v1/oss/attempts/{id}/quiz` | Submit quiz answers; the backend scores them against server-held keys | High (lesson understood) |
| `POST /v1/oss/attempts/{id}/practice-repo` | Body: repository full name. Verifies owner ID, generated from the approved template, not a fork, App installed; creates the issue from the stored variant once | High (repo created, issue created) |
| `POST /v1/oss/attempts/{id}/events` | Extension hints (cloned, branch seen, commit count). Body: `{event_id, type, data}`. At-least-once and idempotent on `event_id`. Always stored as hint | Hint only |
| `GET /v1/oss/attempts/{id}/score` | Score from High milestones and the signed grader result, with the evidence behind each point and the label `Verified` | n/a |
| `POST /v1/webhooks/github` | GitHub `push` and `pull_request` deliveries (public). Signature checked first, deduplicated by delivery ID, unlinked repos ignored | High after the backend re-reads GitHub |
| `POST /internal/grader/results` | Existing endpoint, accepts the new job type `contribution` with a result bound to the head SHA | Signed result |

Conventions that apply here: `Idempotency-Key` on `POST` calls that change state; errors use `{ code, message, recovery, correlation_id }` in plain language (for example "GitHub is not installed on this repository yet. Open the install link and choose only this repository."); rate limits apply to link, quiz, events and practice-repo.

One row per attempt and milestone in the milestone store, with `source` and `trust`. A hint may be upgraded once to High by verified evidence; a High row is never changed or downgraded; a repeated event never awards points twice.

Operator actions (role change, score correction, data export and deletion) use a separate router that requires the `operator` role and writes an audit event.

## AI gateway endpoints (built, in `services/api/app/routers/ai.py`)
All need a signed-in person (Firebase ID token), count against a per-person daily limit and answer with `{ code, message, recovery }` on failure. AI output is only ever a proposal: it is parsed with a strict schema and checked before it is returned, and none of these endpoints scores or awards anything.

| Endpoint | Body | Returns |
|---|---|---|
| `POST /v1/ai/roadmap` | `{kind: job_description or topic, text (1 to 6000 chars), level}` | `{title, steps[]}`. A step is a real lab (`lab_id` from the catalogue) or a lab to generate (at most 4). |
| `POST /v1/ai/interview` | same | `{title, questions[4..10]}`. Each question has `kind` (concept, practical, behavioural), `question`, `hint`, up to 3 `good_answer_covers` and up to 4 `skills`. Practice material only. |
| `POST /v1/ai/explain-error` | `{error_text (1 to 6000), code?, language}` | `{meaning, likely_cause, things_to_try[1..4], concept}`. Guides, never a finished fix. Limit `ai_explain_daily_limit` (60). |
| `POST /v1/ai/review-code` | `{code (1 to 6000), filename?, goal?, language}` | `{summary, strengths[0..3], suggestions[0..6], question_to_think_about}`. A suggestion has `where`, `issue`, `why_it_matters`, `how_to_improve` and a `kind` (bug, readability, safety, style, tests). No rewritten solution and no mark. Limit `ai_review_daily_limit` (20). |
| `POST /v1/ai/paths` | `{goal (3 to 600), level, language}` | `{title, summary, steps[3..8]}`; a step has `id`, `title`, `objective`, `skills`, `minutes`. Skill `path-planner`. Limit `ai_path_daily_limit` (10). |
| `POST /v1/ai/paths/step` | `{goal, path_title, level, language, step {id, title, objective, skills}, previous[]}` | `{intro_md, key_points[3..5], videos[0..2], videos_available, quiz[3], lab}`. Videos are chosen only from YouTube search results and their title, channel and length come from YouTube. `lab` is `{kind: catalog, lab_id, title}` or `{kind: generate, topic}`. Skill `step-builder`. Limit `ai_step_daily_limit` (60). |
| `POST /v1/ai/labs/generate` | `{topic, level}` | A lab that passed generate-and-verify, as a learner view (no protected tests, no reference). Development only until the isolated verifier exists. |
| `POST /v1/tutor/messages` | `{attempt_id, question, level, code?, language}` | `{answer, level}`; the level is lowered to the lab's cap by the server. |

## Credential endpoints (built, in `services/api/app/routers/credentials.py`)
| Endpoint | Purpose |
|---|---|
| `POST /v1/credentials/claim` | Body: `lab_id`, `checks` (id and passed), `started_at`, `completed_at`. Issues tier `attested` when the lab is a catalogue lab with checks, every required check passed and the time is believable. Claiming again returns the same credential. 422 with a plain reason otherwise. |
| `GET /v1/credentials` | The caller's own credentials. |
| `POST /v1/credentials/{id}/sharing` | Body: `public`, `display_name`. Owner only. A public credential needs a name. |
| `GET /c/{id}` | Public page (HTML) for a shared credential. No sign-in. 404 unless shared. |
| `GET /v1/public/credentials/{id}` | The same facts as JSON for a shared credential. |
Tiers: `attested` (checked on the learner's computer, validated by the service, not independently verified) and `verified` (a signed grader result; set only by `upgrade_to_verified`).

## Player page (built, in `services/api/app/routers/player.py`)
`GET /player?v=<11-character video id>&s=<session>` (no sign-in): the page the app opens in a small player window to play one video through the privacy-enhanced `youtube-nocookie.com` player. It counts only seconds played in order and posts `{s, v, watched, duration, ended}` to `POST /player/progress` every 4 seconds. The app creates the session with `POST /v1/player/sessions {video_id}` (signed in) and reads it with `GET /v1/player/sessions/{id}` (owner only). Watched time only grows and is capped at the video length. Strict Content-Security-Policy; any other `v` is a 404.
