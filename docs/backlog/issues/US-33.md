## User story
As the team, the grader rejects forged results, off-list dependencies and tampered tests, and passes our hostile-submission suite.

## Requirements covered
- [ ] `FR-GRADE-007`: Before the pilot, the Grader shall pass sandbox-escape, resource-exhaustion, path-traversal, archive-extraction and result-forgery tests defined in the Test Plan.
- [ ] `FR-GRADE-018`: The evaluator shall not treat AI output, a student's statement or the existence of a file alone as proof that a feature works.
- [ ] `FR-GRADE-020`: The Grader shall build a lab's execution environment from the lab's locked dependency set prepared before grading (prebuilt image or offline package cache) and shall not download packages at grading time; a submission that needs a dependency outside that set shall receive a clear "dependency not allowed" result.
- [ ] `FR-GRADE-021`: The Grader shall run protected tests with a trusted harness that ignores student-supplied test configuration (for example conftest files, pytest plugins and settings), and shall mark the run blocked if the set of executed test IDs differs from the pinned test manifest.
