## User story
As a student, I can run lab tasks that have time and output limits via the local worker, and stop them at any time.

## Requirements covered
- [ ] `FR-EXEC-001`: The Client shall run approved tasks in the lab's declared working directory.
- [ ] `FR-EXEC-002`: Processes shall be started with an executable and an argument list, with a validated working directory; student-controlled values (file names, branch names, text) shall never be interpolated into a shell command string.
- [ ] `FR-EXEC-003`: For tasks run through the managed terminal or task runner, the Client shall record the command, start and end time, exit code and bounded, secret-redacted output.
- [ ] `FR-EXEC-005`: The student shall be able to stop any process the Client started, and the Client shall terminate that process's children where the OS allows.
- [ ] `FR-EXEC-006`: Managed tasks shall have configurable time and output-size limits with defaults set in TBD-13.
- [ ] `FR-EXEC-009`: When a task is blocked by permissions, a missing dependency or a limit, the Client shall say which and suggest a fix.
- [ ] `NFR-SEC-002`: The Client UI layer shall have no direct unrestricted shell or filesystem access; privileged operations shall pass through a narrow, schema-validated interface to the local worker process.
- [ ] `NFR-SEC-003`: The Client UI layer (apps/desktop/lib/ui and lib/features) shall not import dart:io or use Process/File APIs directly; privileged operations (process execution, file access, Git, SQLite sync) shall be handled by a separate local-worker process over a validated, typed IPC contract.
