## User story
As a content author, I write a lab as files and CI proves the starter fails, the reference solution passes and results are repeatable.

## Requirements covered
- [ ] `FR-CONT-001`: Labs shall be stored as files (manifest, guide, tests, reference solution) in a private, version-controlled content repository with access limited to authors and operators, and changes shall be accepted only through reviewed pull requests.
- [ ] `FR-CONT-002`: CI shall validate each lab's manifest against the schema, check that referenced assets and links exist, check prerequisites against the supported toolchain, and check that rubric weights sum to the declared maximum.
- [ ] `FR-CONT-003`: CI shall run the lab's reference solution against the complete test set and shall fail the build if any required test fails.
- [ ] `FR-CONT-004`: CI shall run the lab's starter state against the tests and shall fail the build if the starter does not produce the failures the lab expects.
- [ ] `FR-CONT-005`: CI shall run the test set at least N times (N in TBD-11) against the reference solution and shall fail the build if results are inconsistent.
- [ ] `NFR-MAINT-002`: Adding a lab shall require only content files (manifest, guide, tests) and CI, with no Client release.
- [ ] `NFR-LEGAL-002`: Lab text shall not state or imply that a third-party service is free, unlimited or permanently available; it shall point to the provider's current terms and show a last-verified date.
