## User story
As a student, I can sign in with my Google account through my browser, so that I do not create a new password.

## Requirements covered
- [ ] `FR-AUTH-001`: The Client shall offer Google sign-in using the system browser and the identity provider's supported native-application flow; an embedded web view shall not be used for sign-in.
- [ ] `FR-AUTH-002`: The Client package shall contain no confidential OAuth client secret and no backend credential.
- [ ] `FR-AUTH-003`: The sign-in request shall ask only for the identity scopes needed for sign-in (OpenID, profile, email).
- [ ] `FR-AUTH-004`: The backend shall validate the signature, issuer, audience and expiry of the session token on every protected request and shall reject invalid, expired or revoked tokens.
- [ ] `FR-AUTH-005`: The backend shall map a verified identity to a stable internal user ID using the provider's stable subject identifier, shall not use email address as the account key, and shall not create duplicate accounts for the same subject.
- [ ] `FR-AUTH-006`: Sign-out shall remove all local session material, and a revoked or expired session shall be denied by protected APIs.
- [ ] `FR-AUTH-007`: Session material shall be persisted only in OS-backed secure storage; if only weak storage is available, the Client shall not persist it and shall require sign-in on next start.
- [ ] `FR-AUTH-008`: The Client shall distinguish cancelled sign-in, network failure, expired session and unverified email, and shall show a recovery action for each.
- [ ] `FR-AUTH-009`: The backend shall determine roles from server-controlled data; a role or permission supplied by the Client shall be ignored.
- [ ] `NFR-SEC-004`: Secrets shall be stored only in OS-backed secure storage or a server-side secret manager; plaintext storage shall not be a default or fallback.
- [ ] `NFR-SEC-006`: The backend shall enforce authorisation on every protected operation and shall deny by default when token or role validation fails.
